# Phase 8: promptable steps

Run **one numbered step per prompt**, then stop. This file breaks down Phase 8 of `ROADMAP.md`; it does not authorize implementation, cloud provisioning, a commit, or a push. Read `AGENTS.md`, the root project documents, approved decisions, current code, and Phase 1–7 evidence before acting. Preserve the eight prescribed services and simulated-only behavior. Record actual checks and limitations after each step. Phase 9 remains separate.

1. **Settle the integrated design and cloud preflight.** Trace the existing service contracts and Terraform roots into one Phase 8 deployment plan. Decide the EKS/network layout, private connectivity to MSK/EMR, ZooKeeper, SQL, DynamoDB, S3, SQS/Lambda, service identities/secrets, HTTPS public entry and access controls, container packaging, and Terraform-versus-GitOps ownership. Identify any material architecture/interface changes for approval. Check current AWS access, quotas and account/region; prepare a concrete resource inventory, lifecycle/teardown plan, and current cost estimate against the binding total cap and reserve. **No apply.** Done when the design, costs, gates and likely files are reviewable. **Prompt:** `Do Phase 8 step 1 from "phase 8 steps.md" only: prepare the integrated design, access/cost preflight and approval decisions. Do not provision resources. Then stop.`

2. **Prepare and validate cloud IaC.** Following approved Step 1 decisions, finish Terraform ownership for all required cloud resources and connectivity, including EKS, existing data/processing resources, IAM, security, public HTTPS and an IaC-owned GitOps bootstrap. Package the six Kubernetes services and wire their runtime configuration without creating resources. Run format, validate, plan or mocked checks and focused packaging tests. Produce an exact apply and teardown plan with an updated cost preflight. **No apply.** Done when the planned resources and deployment procedure are reviewable. **Prompt:** `Do Phase 8 step 2 from "phase 8 steps.md" only: prepare and validate the integrated Terraform and service packaging. Do not apply or deploy. Then stop.`

3. **Prepare GitOps and integrated verification.** Add Git-tracked manifests for all six Kubernetes applications, their configuration, health/readiness and private service routing. Configure ArgoCD or Flux to own every application deployment and update; document the Git reconciliation path and prohibit direct `kubectl apply` of applications. Build a repeatable cloud demo/check script for the public API, REST/gRPC, Kafka → EMR Flink → results, recommendation/analytics, incident/congestion → SQS → Lambda, three storage products, and ZooKeeper failover. Run local/static checks and verify the exact cloud test and cleanup plan. **No apply.** Done when manifests and tests are ready for a separately authorized cloud run. **Prompt:** `Do Phase 8 step 3 from "phase 8 steps.md" only: prepare GitOps manifests and the integrated cloud acceptance/demo workflow. Do not deploy. Then stop.`

4. **Deploy and verify the integrated cloud MVP.** Only after the Step 1–3 plan and current cost/access gates are reviewed and this cloud run is explicitly authorized, apply IaC, bootstrap GitOps, and let GitOps deploy the six applications. Verify all eight runtimes in their approved locations, a secured public HTTPS URL, both end-to-end paths, actual SQL/NoSQL/object use, ZooKeeper takeover, and a Kubernetes application update reconciled from Git. Save commands/results and track spending. Follow the approved lifecycle/teardown plan, audit run-owned resources and state, and report any unmet check or cleanup issue. **Prompt:** `Do Phase 8 step 4 from "phase 8 steps.md" only: execute the separately approved integrated cloud run, capture acceptance evidence, and perform the reviewed teardown/audit. Stop if a required access, cost or authorization gate fails. Then stop.`

5. **Audit acceptance and close Phase 8.** Compare every Phase 8 roadmap criterion with actual evidence; fix only demonstrated Phase 8 defects and rerun affected checks. Align README, approved architecture changes, deployment/demo instructions and `ROADMAP.md`. Create `docs/progress/phase-8.md` within the AGENTS.md 200–300-word maximum, including work, decisions, tests, limits and next steps. Mark Completed only if all Phase 8 criteria pass; otherwise record In Progress or Blocked with the gap. **Prompt:** `Do Phase 8 step 5 from "phase 8 steps.md" only: audit Phase 8 acceptance, finish required documentation and record the accurate status. Do not start Phase 9, commit or push. Then stop.`

The Phase 8 MVP gate does not include Phase 9 HPA/load proof or finalized monitoring/logging, or Phase 10 submission work. Basic health and diagnostic logs are needed for the Phase 8 run.
