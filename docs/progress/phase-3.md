# Phase 3 - Completed (real local integration and unapplied IaC)

Phase 3 implements Traffic Ingestion and a single Event Publisher under the user-approved local Docker scope. REST readings are validated against active Registry sensors, normalized without replacing IDs/timestamps, sent through actual gRPC, archived as deterministic JSON and published to Kafka. Success requires both archive and Kafka acknowledgement. Same-ID conflicts are rejected; uncertain outcomes/retries can produce Kafka duplicates.

Important work includes both service packages, shared wire validation and generated protobuf types, `scripts/demo_phase3.py`, deterministic generation/inspection tools, persistent Kafka/SeaweedFS Compose, and `infrastructure/terraform/phase3/`. Configuration, dependency pins, smoke checks, README, architecture, decisions and roadmap were updated. MSK/S3/topic/IAM preparation consumes Phase 2 network outputs; no duplicate VPC/RDS or cloud resources were created.

Verification: `.venv\Scripts\python -m unittest discover -s tests -v` passed 31 tests; `scripts\smoke.py` passed all eight entry points; the Phase 2 restart/outage demo and `-m pip check` passed. The full `scripts\demo_phase3.py --failure-tests` run consumed real Kafka records and retrieved actual archived bytes, including invalid-reference rejection, concurrent conflicts, Publisher/container restarts, dependency outages and deliberately lost acknowledgement. Saved evidence reports eight logical events, fourteen Kafka records and six duplicates. Independent consumer/archive inspection also passed. Both Terraform roots passed formatting/validation and two mocked tests each; no AWS-backed plan/apply ran.

Initial Kafka startup failed on named-volume permissions; local configuration was corrected without deletion. Broker-disconnect logs during outage tests are expected. Starlette's existing TestClient deprecation warning remains non-failing. MSK/AWS S3, IAM/TLS, regional compatibility, Linux packaging and actual cost remain unverified. The US$5 cap remains binding. No Flink processing, recommendations, alerts, election or HPA was added. Phase 4 remains Not Started and requires separate authorization.
